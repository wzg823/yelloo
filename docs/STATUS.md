## 1. 一句话结论

**核心闭环已经跑通并且在真实服务器上验证过：注册 → 发帖 → 附件 → 跨用户实时送达 → 历史分页 → 搜索 → 备份。**

现在缺的不是"能不能用"，而是**开放注册前的治理能力**：编辑删除、管理后台、举报处置、密码找回。
反垃圾的第一道闸（新人限流）已经装好，剩下的三项是一条链，缺任何一环都会在开放注册第一天失控。
再之后是**增长能力**（forum 一帖一 URL、语法高亮）—— 不做就没有自然流量。

**部署方式的转变是这一阶段最大的工程收益**：服务器从"构建机"变回"运行机"。
此前在 1.6GB 机器上直接 `docker compose build` 导致过内存耗尽、ssh 失联，
必须走控制台重启才恢复。现在构建在 WSL（15.9GB 内存）完成，服务器只做 `docker load`，
整个过程内存压力接近于零。

**验证脚本的分工**（这套结构比脚本本身更值钱）：

| 脚本 | 手段 | 覆盖什么 |
|---|---|---|
| `test-trust.mjs` | 纯函数 + 注入假时钟 | 时间边界（10 分钟 / 24 小时精确到毫秒）、配额、豁免、计数器 key 隔离 |
| `test-message-list.mjs` | 纯函数 | 去重、乐观认领、"变更必须覆盖而不是跳过" |
| `test-admin-policy.mjs` | 纯函数 | **防横向提权**、时长解析、频道输入规范化 |
| `test-reset-policy.mjs` | 纯函数 | 令牌熵、一次性、限期边界、邮箱脱敏、邮件正文 |
| `verify-reset.mjs` | 真实 HTTP + 查库 | 不可枚举（逐字节比对）、只存哈希、一次性、会话撤销 |
| `verify-newuser.mjs` | 真实 HTTP | 门卡确实接在路由上；含**正向控制**防止"全站被拦"也全绿 |
| `verify-messages.mjs` | 真实 HTTP + Caddy | 权限边界、修订历史、附件文件真删、搜索不命中 |
| `verify-admin.mjs` | 真实 HTTP | 每个管理接口的越权防护、等级关系、封禁当场生效、审计留痕 |
| `smoke.mjs` | 真实 HTTP + SSE | 跨用户实时投递与心跳，以及编辑/删除会不会广播 |
| `verify-attachments.mjs` | 真实 HTTP + Caddy | 写入 → 卷 → 反向代理直出 三处对齐 |

一个只做纯函数测试的策略层证明不了它被调用了；一个只打 HTTP 的测试又没法
验证"恰好第 600 秒"这种行为。两者都在，才覆盖得住。
