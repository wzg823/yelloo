## 1. 这是什么

**一个面向中文开发者的公开技术社区。**

一句话概括形态：**内部是 Discord 式的频道模型，对外是论坛式的 URL 结构。**

这个组合不是随意拼的，而是为了解决一个具体矛盾：

> 频道制的滚动时间线适合实时讨论，但**天然不利于搜索引擎收录**；
> 而公开技术社区最依赖的就是自然搜索流量 —— 程序员遇到问题会去搜。

Discord 对这个矛盾的答案是"不做 SEO"（它是私密社群工具）。我们不能这么做，所以：

| 层 | 采用 | 目的 |
|---|---|---|
| 数据模型 | 频道 → 连续消息流 + Thread | 实时讨论体验 |
| URL 结构 | `/c/[slug]`、`/m/[id]`、`?before=` 游标分页 | 每条讨论都有可被收录的独立地址 |
| 渲染方式 | 服务端渲染真实 HTML（非客户端 fetch） | 爬虫能看到完整内容 |

**可见性**：读完全公开（含游客），写需登录。
**规模目标**：单机起步，万级注册用户 / 千级日活 —— 这个目标决定了"先不引入什么"。

## 2. 技术栈

| 层 | 选型 | 为什么 |
|---|---|---|
| 框架 | **Next.js 15 (App Router) + React 19 + TypeScript** | 论坛重 SEO，需要服务端渲染；Route Handler 省掉一整套独立后端 |
| 数据库 | **PostgreSQL 16** | 内置 GIN + `pg_trgm` 就能做中文搜索，不需要 Elasticsearch |
| ORM | **Drizzle** | 类型安全且 SQL 可控；迁移是纯 SQL 文件，方便 review |
| 实时 | **SSE**（不是 WebSocket） | 只需服务端单向推送；原生重连 + `Last-Event-ID`，实现量小一个数量级 |
| 实时扇出 | **进程内 Map**（挂在 `globalThis`） | 单实例够用。扩展路径已设计好：Postgres `LISTEN/NOTIFY`，**不需要 Redis** |
| 密码 | **argon2id**（`@node-rs/argon2`） | 预编译二进制，Docker 构建不需要编译工具链 |
| 会话 | **数据库会话**（Cookie 只放不透明 token，库里存 SHA-256） | 论坛需要"封禁立即生效"，JWT 在过期前无法撤销 |
| 反代 | **Caddy 2.8** | 自动 HTTPS；SSE 只需 `flush_interval -1` 两行配置 |
| 样式 | **原生 CSS + CSS 变量** | 零构建配置，`next build` 少一个失败点；配色用 `light-dark()` 一份定义管两套主题 |
| 容器 | **Docker Compose 单机**（app / postgres / caddy） | 单机四个月内不需要编排系统 |
| 运行时 | Node 22（bookworm-slim 镜像） | 原生支持 TS 类型擦除，运维脚本可以直接跑 `.ts` |

### 刻意没有引入的东西

**Redis、Kafka、Elasticsearch、K8s、GraphQL、Tailwind、状态管理库、ORM 之外的数据层。**

在单机 + 万级用户之前，它们都是负债。每一条都有明确的"什么时候才该引入"的触发条件（见第 7 节）。

## 4. 架构要点

### 4.1 消息 ID 用 Snowflake，不是自增

`messages.id` 是 64 位 Snowflake（时间戳 + worker + 序列号）。带来两个简化：

- 游标分页只需一个索引：`WHERE channel_id = ? AND id < ? ORDER BY id DESC`
- SSE 断线补齐不需要额外的事件表：`WHERE id > :lastEventId`

代价：**JS 侧必须用 BigInt，出 JSON 必须转字符串**（`Number` 只有 53 位安全整数）。
全链路已处理，约定写在 `src/lib/serialize.ts`。

### 4.2 实时：一条 SSE 连接，多路复用

浏览器对同源 HTTP/1.1 只有 6 条连接。每个频道各开一条 `EventSource` 的话，
用户切到第 7 个频道就会把页面其他请求全部饿死。所以：

- 每个登录用户只维持 **1** 条 `/api/events` 连接
- 服务端按"该用户可见的频道集合"过滤后推送
- 断线重连靠 `Last-Event-ID` 补齐；SSE 被拦截时自动降级为 5 秒轮询

**一个必须区分的细节**：`message.created` 要按 id **去重**，
而 `message.updated` / `message.deleted` 必须按 id **覆盖** —— 两者语义相反，
共用一个回调会让"变更"被去重逻辑静默丢弃（表现为别人看不到你的编辑与删除，
而连接状态还显示"实时已连接"）。

### 4.3 权限分两层

```
permissions.ts   回答"有没有这个能力"（bigint 位域）
admin-policy.ts  回答"能不能对「这个对象」用这个能力"（等级关系）
```

只有能力位就会出现**横向提权**：版主封版主、管理员互相封禁。双方都"有权限"，
日志上看起来全都合法。三条规则：不能处置自己、只能处置等级严格低于自己的、
不能把别人提到与自己同级或更高。

### 4.4 删除是清库，不只是 API 层过滤

软删除时在同一个事务里：把删除前的正文记入 `message_edits`（管理侧可查，
公开 API 拿不到）、删附件记录、**真正清空 `content_md`**、置 `is_deleted`。
附件文件在事务提交后才 unlink（反过来做，一旦回滚就会留下 404 附件）。

只在序列化层过滤是不够的：任何绕过它的查询都能读到原文 —— 搜索、导出、
将来随手写的统计脚本都可能是那条路径。

### 4.5 主题不闪白

用户的选择存 Cookie（不是 localStorage），服务端渲染时读出来直接落成
`<html data-theme>`，第一帧就是对的。配色用 CSS 的 `light-dark()`：
同一个变量的两档取值写在一行，**不可能出现"改了深色忘了浅色"**。

## 6. 质量保障

没有单元测试框架，也没有 CI。取而代之的是 **11 个可独立运行、任何一个失败都会
以非零码退出的脚本，共 397 项断言**。它们被刻意分成两类：

### 纯函数测试（5 个，1,050 行）—— 毫秒级，不需要数据库

| 脚本 | 项数 | 覆盖 |
|---|---|---|
| `test-trust.mjs` | 48 | 新人限流的时间边界（10 分钟 / 24 小时，精确到毫秒）、配额、员工豁免、计数器 key 隔离 |
| `test-message-list.mjs` | 30 | 消息列表去重、乐观认领、"变更必须覆盖而不是跳过" |
| `test-admin-policy.mjs` | 95 | **防横向提权**穷举（管理员↔管理员、版主↔版主、成员↔成员 × 各种动作）、时长解析、频道输入规范化 |
| `test-reset-policy.mjs` | 38 | 令牌熵、一次性、限期边界、邮箱脱敏、邮件正文 |
| `test-theme.mjs` | 15 | 主题解析、脏 Cookie 回退、Cookie 的 `Path` 必须是 `/` |

### 端到端验证（6 个，约 1,900 行）—— 打真实 HTTP，跑在真实容器里

| 脚本 | 项数 | 覆盖 |
|---|---|---|
| `smoke.mjs` | 27 | 跨用户实时投递、心跳（诊断中间层缓冲）、编辑/删除广播、SEO 基础 |
| `verify-newuser.mjs` | 15 | 门卡确实接在路由上；含**正向控制** |
| `verify-messages.mjs` | 34 | 权限边界、修订历史、**附件文件真删**、搜索不命中 |
| `verify-admin.mjs` | 53 | 每个管理接口的越权防护、等级关系、**封禁当场生效**、审计留痕 |
| `verify-reset.mjs` | 24 | 不可枚举（逐字节比对）、**只存哈希**、一次性、会话撤销 |
| `verify-attachments.mjs` | 18 | 写入 → 卷 → Caddy 直出 三处对齐 |

### 为什么分成两类

**只做纯函数测试的策略层证明不了它被调用了；只打 HTTP 的测试又验证不了
"恰好第 600 秒"这种行为。** 两者都在，才覆盖得住。

这套结构抓到过几个真实缺陷，都属于"看起来正常工作"的那一类：

- 变更事件被客户端去重逻辑丢弃（别人看不到编辑与删除）
- `smoke.mjs` 在 Linux 上不退出（提前失败时报 154 秒才被杀）
- 登录限流把成功登录也算进额度（共享出口 IP 的人会被集体锁 15 分钟）
- 缺 `DATABASE_URL` 时连 `next build` 都过不去（模块级建立连接池）
- 管理接口把内部 camelCase 字段直接透传（客户端静默拿到 `undefined`）

### 另外的自动闸门

- `npm run typecheck`（`tsc --noEmit`）
- `next build`（**无数据库条件下必须通过** —— 这条性质曾经失效过，已修）
- 部署脚本在重启前先 `caddy validate`；健康检查失败则不许报"部署成功"

## 7. 部署与运维现状

### 工作流：本地构建，服务器零构建

```
WSL2（15.9GB 内存）                    AWS Lightsail（1.6GB）
──────────────────                     ────────────────────
npm run build:image                    上传 207MB 镜像归档
  → docker build app/migrate/seed         → docker load
  → 导出 tar.gz（207MB）                  → migrate → seed → 重启
                                          → 健康检查 → 可选 smoke
npm run deploy:local -- -Server ... -Images -Smoke
```

**服务器端完全不构建。** 这不是洁癖，是被事故逼出来的：在 1.6GB 机器上直接
`docker compose build`，`next build` 峰值约 1.8GB，与 Postgres/Caddy 共存必然
swap 抖动 —— 实测导致过 sshd 无法完成握手，必须走云控制台重启才恢复。
现在服务器只做 `docker load`（纯磁盘写入），内存压力接近于零。

### 成本

VPS（新加坡 2C2G）+ 域名 ≈ **$6~8/月**。

### 备份

`scripts/backup.sh` / `restore.sh`（`pg_dump` + 附件卷）。
**当前只在本地留档，没有推到对象存储** —— 这是待办。

## 8. 已知限制与风险

### 必须在上线前处理

| 级别 | 事项 |
|---|---|
| 🔴 | **ICP 备案尚未开始**。大陆服务器未备案域名会被直接阻断，且备案本身要等 |
| 🟠 | **代码只有一个远端副本**（GitHub 公开仓库），且**没有任何异地数据备份** |
| 🟠 | 测试残留数据：11 个账号里有一批演示与验证账号，37 条消息含墓碑与测试频道 |
| 🟡 | 邮件默认不发（`MAIL_TRANSPORT=log`）：密码重置流程完整，但用户收不到信。配好通道即生效，代码不用改 |

### 有意为之的取舍（不是遗漏）

- **不提供删除频道**：外键是 `onDelete: cascade`，物理删除会连带删掉全部消息与修订历史。要"删"就归档
- **不提供把某人提升为管理员**的界面：必须走 `scripts/promote.mjs`。否则一个被盗的管理员账号能立刻造出第二个管理员
- **频道 slug 不可修改**：它是对外 URL，改了会让已收录的链接全部 404
- **删除不可逆**：正文清空、附件文件删除。删除前的最后一版留在 `message_edits`（管理侧可查），所以"处置留痕"与"用户真的删掉了"可以同时成立
- **编辑与删除不在 SSE 补齐范围内**：补齐按 id 增量，而它们不产生新 id。客户端在重连后与降级轮询期间重取可见窗口来兜住
- **限流是进程内的**：`docker compose restart app` 会清空额度。单实例下可忽略
- **forum 类型频道**目前与 text 行为一致，未做"一帖一帖"的独立 URL（P3）
- **反应、@提及、RSS、用户主页**：只有表结构或完全未开始（P3）

### 只有人能做的验证

**客户端交互目前只在服务端与 HTML 层面验证过，没在真实浏览器里点过一遍**
（编辑、举报、删除、管理后台四个表单、主题切换的观感）。
这是整个项目里唯一没被自动化覆盖的环节。

搜索剥离到 Meilisearch（消息 > 1000 万行）、附件转对象存储（附件卷 > 20GB）、
消息表分区（首屏 p95 > 50ms）。

## 10. 快速上手

```bash
# 本地开发
npm install && cp .env.example .env   # 至少改 DATABASE_URL，生成 SESSION_SECRET
npm run db:migrate && npm run db:seed
npm run dev                           # → http://localhost:3000

# 质量闸门（不需要数据库）
npm run typecheck
npm run test:trust && npm run test:list && npm run test:admin
npm run test:reset && npm run test:theme

# 端到端（需完整环境）
docker compose exec -T app node scripts/smoke.mjs
```

线上入口与账号信息不写在文档里 —— 见 `docs/DEPLOY.md` 与部署环境的 `.env`。
